# WorkFlow — Система управления заявками (Этапы 1–5: Nuxt 4 + Nitro + PostgreSQL + Auth + RBAC + Testing)

Полный проект системы управления обращениями **WorkFlow**, последовательно дополненный функционалом **Этапов 1, 2, 3, 4 и 5** в единой кодовой базе строго по техническому заданию и исходным макетам (`1280px`, `768px`, `360px`), с вынесенными в отдельные файлы CSS-стилями (`app/assets/css/`).

---

## Что реализовано в Этапе 5 (Debugging, testing и надёжность)

### 1. Документация найденных багов (Шаги воспроизведения, Root Cause и Исправление)

#### Баг №1 — Двойная отправка комментария при быстрых повторных кликах
- **Шаги воспроизведения**:
  1. Открыть карточку любой заявки (`/requests/1042`).
  2. Ввести текст в поле «Ваш комментарий» и быстро дважды нажать кнопку «Отправить комментарий» (или вызвать отправку повторно до завершения сетевого запроса).
- **Предполагаемая причина (Root Cause)**:
  - Проверка реактивного флага `isSubmittingComment` без синхронного мьютекса и без серверного ключа идемпотентности (`idempotencyKey`) позволяла двум быстрым вызовам в одном тике событийного цикла пройти проверку и создать дублирующие записи комментария на сервере.
- **Исправление и Regression Test**:
  - В `shared/utils/asyncGuards.ts` добавлен синхронный блокировщик `createSubmissionLock()`, мгновенно захватывающий лок и генерирующий уникальный `idempotencyKey`.
  - В `server/api/requests/[id]/comments.post.ts` и `server/api/comments/index.post.ts` добавлена серверная дедупликация по `idempotencyKey` (`isDuplicateCommentKey` / `registerCommentKey` в `server/utils/auth.ts`).
  - Регрессионный тест: `tests/integration/regressionBugs.test.ts` (`Regression Bug #1`).

#### Баг №2 — Устаревший ответ поиска перезаписывает более новый результат (Race Condition)
- **Шаги воспроизведения**:
  1. На странице `/requests` быстро ввести поисковый запрос `CRM` (запрос №1 уходит на сервер и обрабатывается дольше).
  2. Сразу изменить строку поиска на `1041` (запрос №2 уходит позже, но возвращается быстрее).
  3. Когда медленный ответ на запрос №1 приходит после ответа №2, таблица заявок перезаписывается устаревшими данными от запроса №1.
- **Предполагаемая причина (Root Cause)**:
  - Отсутствие отмены предыдущего in-flight запроса через `AbortController` и отсутствие сверки порядкового идентификатора запроса (`requestId`) перед записью ответа в состояние списка.
- **Исправление и Regression Test**:
  - В `shared/utils/asyncGuards.ts` реализован `createSearchRaceGuard()`, который увеличивает монотонный `requestId`, вызывает `abort()` у предыдущего `AbortController` и проверяет `isLatest(requestId)` перед обновлением списка заявок в `app/pages/requests/index.vue`.
  - Регрессионный тест: `tests/integration/regressionBugs.test.ts` (`Regression Bug #2`).

#### Баг №3 — Доступ к приватному маршруту после `logout`
- **Шаги воспроизведения**:
  1. Войти в систему и перейти в `/profile`.
  2. Нажать кнопку «Выйти из аккаунта» (`POST /api/auth/logout`).
  3. Перейти по прямой ссылке или кнопкой «Назад» браузера на `/requests` или `/dashboard`.
- **Предполагаемая причина (Root Cause)**:
  - При выходе в `clearServerSession` (`server/utils/auth.ts`) cookie `wf_session` переводилась в `logged_out`, но вспомогательная cookie `wf_role` оставалась в браузере, а на клиенте `authStore` не синхронизировал принудительный сброс с cookie `wf_session=logged_out`.
- **Исправление и Regression Test**:
  - В `server/utils/auth.ts` при `clearServerSession` очищается и `wf_session`, и `wf_role` (`maxAge: 0`).
  - В `app/stores/auth.ts` и `app/middleware/auth.global.ts` добавлена строгая проверка `wf_session=logged_out` / `wf_session=expired`, мгновенно обнуляющая `authenticated` и `user` и перенаправляющая неавторизованного пользователя на `/login`.
  - Регрессионный тест: `tests/integration/regressionBugs.test.ts` (`Regression Bug #3`) и `tests/e2e/workflow.spec.ts`.

#### Баг №4 — Потеря или рассинхронизация состояния после `refresh` страницы
- **Шаги воспроизведения**:
  1. Войти под ролью `Client` (`client@mail.demo`) или применить фильтры/поиск в URL (`/requests?search=CRM&status=new&priority=high`).
  2. Выполнить полную перезагрузку страницы (`F5` / `Ctrl+R`).
- **Предполагаемая причина (Root Cause)**:
  - При SSR-запросе в `authStore.fetchSession()` не пробрасывались заголовки `cookie` (`useRequestHeaders(['cookie'])`), а на сервере при перезапуске dev-сервера токен `sess_<userId>_<timestamp>` не восстанавливал пользователя по `userId`, сбрасывая роль на дефолтного Оператора.
- **Исправление и Regression Test**:
  - В `app/stores/auth.ts` добавлена передача SSR-заголовков `useRequestHeaders(['cookie'])` и флаг `sessionRestored`.
  - В `server/utils/auth.ts` добавлено восстановление пользователя из токена `sess_<userId>_<timestamp>`, а в `useRequests.ts` — синхронная инициализация фильтров из `route.query`.
  - Регрессионный тест: `tests/integration/regressionBugs.test.ts` (`Regression Bug #4`).

#### Баг №5 — Потеря введённых данных и отсутствие обработки ошибок `500`, `401` и `409` при создании и изменении заявки
- **Шаги воспроизведения**:
  1. Открыть модальное окно «Новая заявка» и попытаться отправить форму с пустым названием/описанием или при временной ошибке сервера `HTTP 500`.
  2. Изменить приоритет заявки при параллельном изменении другим сотрудником (`HTTP 409`) или при истёкшей сессии (`HTTP 401`).
- **Предполагаемая причина (Root Cause)**:
  - В `useRequests.ts` метод `createNewRequest` перехватывал и подавлял ошибку `POST /api/requests` (`catch {}`), закрывая модальное окно вместо отображения плашки ошибки и кнопки «Повторить» по макету 5 этапа.
- **Исправление и Regression Test**:
  - В `WFGPTCreateRequestModal.vue` реализованы все 3 состояния из макетов `workflow 5 заданеи.zip`:
    1. **Ошибка ввода**: валидация полей `Укажите название заявки.` и `Опишите проблему.` (`#FF80A3`) с блокировкой кнопки отправки;
    2. **Отправка**: кнопка переходит в состояние `disabled` с текстом `Создаём…`;
    3. **Ошибка сохранения и повтор (`500` / `409`)**: введённые данные сохраняются в форме, отображается блок `#38213D` / border `#DE5994` `Не удалось сохранить изменения. Данные не потеряны. Повторите попытку.`, а кнопка меняет текст на `Повторить`.
  - При ответе `HTTP 401` вызывается `authStore.handleUnauthorizedError()` с редиректом на `/login?expired=1` и показом баннера `Сессия истекла. Войдите снова, чтобы продолжить работу.`.
  - Регрессионный тест: `tests/integration/regressionBugs.test.ts` (`Regression Bug #5`).

## Тестирование и проверка

Все стили компонентов и страниц вынесены в отдельные `.css` файлы в `app/assets/css/`.

```bash
# Запуск unit и integration/regression тестов
npm test

# Проверка типов TypeScript (клиент + сервер + shared)
npm run typecheck

# Запуск Playwright E2E-сценария (login -> create request -> assign -> change status -> comment -> logout)
npm run test:e2e
```
